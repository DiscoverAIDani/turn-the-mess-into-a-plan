Devpost project reference · Offline app map

From messy notes to a clear next step

A single-screen app turns supplied notes into a goal, up to three priorities, a checklist, and matters needing attention. The browser keeps current work; a local Express server asks Nemotron for a plan and validates the response.

Source snapshot: 325fa84 (Slice 3), plus the approved final-review coverage and prompt correction included with this map. Prepared September 29, 2026. This reference can drift as code changes. Final whole-app review passed; this is a reference route, not a record of a completed hands-on tour.

One action: make a replacement plan

  1. 1 → Requestpublic/app.js · makePlan / generate

    Check input and confirm when tasks are completed. Send notes to POST /api/plan; retain current work while waiting.

  2. 2 → Generate and validateserver/nebius.js · generatePlan

    Nebius runs nvidia/Nemotron-3_5-Lightning with thinking disabled and a 15-second timeout. validatePlan checks structure, grounding, and source-action coverage.

  3. 3 → Replace or preservepublic/plan-state.js · accept / fail

    A valid plan or no-action result replaces the old result and resets checks. Failure preserves work. renderWork displays success; saveWork saves it locally.

Browser storage: public/storage.js · createStorage uses only messy-plan:v1. Confirmed Start Over invalidates pending requests and removes that entry. Temporary errors, loading, and dialogs are not saved.

Three stops in the code

  1. public/app.js — search async function generate. Follow the success path into work.accept, rendering, and saving; compare the catch path into work.fail.
  2. public/plan-state.js — search accept(id, result) and fail(id). Only acceptance replaces the result and clears completion. Request identity rejects stale responses.
  3. tests/result-lifecycle.test.js — find valid no-action replacement removes the plan and its completion and failure preserves the exact previous plan and completion for manual retry. These tests encode the two different outcomes.

To change this, start here

  • Screen layout and styling: public/index.html and public/styles.css. Result text rendering: renderResult.
  • Save, restore, or clear behavior: createStorage, coordinated by saveWork and the clear handler in public/app.js.
  • Response acceptance rules: validatePlan, hasGroundedTemporalLanguage, and hasExplicitSourceCoverage. Coverage now recognizes coordinated action clauses; the prompt contrasts descriptive context with explicit actions and actual appointments. Temporal and exact-excerpt checks remain unchanged.

A practice to reuse

Write down what must change and what must survive before implementing a state transition. Here, the PRD distinguishes a valid no-action replacement from a failed request. The lifecycle tests above make that distinction observable, while tests/storage.test.js checks that saved work follows it. Use the same approach for another app's save, retry, or reset behavior.

Passing deterministic checks verifies these programmed rules. It does not establish universal model accuracy: recurrence rejection, occasional poor ordering, and conservative source coverage remain documented limitations.

Run and revisit

From the project folder, install dependencies with npm.cmd install if needed. Copy the blank-key .env.example to local .env only if it does not exist, and enter your own Nebius key locally. Keep the configured Nemotron model. Run npm.cmd start, then open http://127.0.0.1:3000. New generation needs internet and usable credits.

Existing checks: npm.cmd test and node --env-file=.env scripts/verify-browser.mjs --lifecycle-only. The latter uses installed Chrome with simulated results and makes no provider calls.
